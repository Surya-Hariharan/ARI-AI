Create a two-module Android project skeleton for a privacy-first AI system called ARI, consisting of:

ARI Control App (MASTER NODE)

ARI Companion Core (SLAVE NODE)

This project is an architectural scaffold, not a feature-complete app.

The primary goal is to enforce a hard separation between intelligence and authority.

CORE SYSTEM PRINCIPLE (NON-NEGOTIABLE)

The Control App is the only authority

The Companion Core is intelligent but powerless

The Companion can only request actions

The Control App decides whether actions are allowed

The Companion can NEVER:

Access system APIs directly

Open apps

Change permissions

Talk to backend services

Modify its own capabilities

This must be reflected structurally in the code.

MODULE 1 — ARI CONTROL APP (MASTER)

Role

Acts as the root of trust

Enforces permissions, policies, and security

Owns all system-level access

Tech

Android

Kotlin

Jetpack Compose

MVVM architecture

Responsibilities

User account & authentication (mocked)

Device binding (mocked)

Voice enrollment & retraining (mocked)

Capability registry (app allow/deny toggles)

Audit & activity logs

Kill switch (disable ARI completely)

Explicit Constraints

No AI models

No intent parsing

No autonomous behavior

No wake-word detection

UI SCREENS

Landing / Status Dashboard

Permissions (list of installed apps with allow/deny toggles)

Voice Profile (enrollment & verification strength)

Activity / Audit Log

Account & Security

Advanced / Kill Switch

Permissions Page Requirement

Display installed apps

Each app must have toggle switches

Toggles control what ARI is allowed to request

All enforcement logic lives here

MODULE 2 — ARI COMPANION CORE (SLAVE)

Role

Performs intelligent operations

Has NO authority

Runs as a foreground service

Tech

Android

Kotlin

No UI screens

Responsibilities

Wake-word detection (mocked)

Speaker verification (mocked)

Intent interpretation (mocked)

Generate action requests

Explicit Constraints

No direct system API calls

No permission storage

No backend access

No UI except a visual activation overlay

ARI VISUAL ACTIVATION (SYSTEM OVERLAY)

When ARI is triggered, show a screen-edge glow overlay

Overlay must:

Not block the current app

Have animated glowing edges

Indicate states: Listening / Processing / Denied / Success

Overlay disappears automatically after interaction

This overlay belongs to the Companion Core, but is enabled/disabled ONLY by the Control App.

COMMUNICATION MODEL (CRITICAL)

Use Bound Services / IPC

Companion sends action requests

Control App returns ALLOW / DENY

Companion never executes actions itself

Example:

Companion → "Request OPEN_APP: Maps"
Control App → "DENIED"


All final execution must be done by the Control App.
